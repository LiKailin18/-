# 毕业设计课题任务书（开题报告）

**课题名称：基于大语言模型的智能学习辅助系统设计与实现**

**学生：李凯琳**

---

## 一、课题背景与意义

随着高校课程资料逐步数字化，学生面对的学习材料从纸质教材扩展到 PDF 讲义、Word 文档、
课件与笔记等多种形态。资料数量增长的同时，带来两个现实问题：一是**资料管理与检索成本高**，
同一门课的资料分散在不同目录、不同格式中，复习时难以快速定位；二是**知识理解效率低**，
长文档中真正需要掌握的定义、公式与结论往往被大量重复内容淹没，学生需要反复通读才能提炼要点。
传统的学习管理工具多停留在"存文件、记待办"的层面，无法对内容本身提供理解层面的帮助。

大语言模型（Large Language Model, LLM）的出现，使"理解学习内容"成为可以被工程化的能力：
模型可以对资料做总结、围绕资料回答问题、依据资料出题，并根据学习数据给出改进建议。
但把 LLM 真正接入学习系统，并不是调用一次聊天接口那么简单——需要解决**资料如何被模型可靠读取**、
**模型输出如何被校验与约束**、**调用成本与失败如何被度量与降级**、以及**生成内容如何与用户数据隔离**等工程问题。

本课题的目标，是设计并实现一套面向高校学生的智能学习辅助系统：把「资料管理—学习计划—任务执行—
学习记录—统计分析」的学习闭环，与「问答、总结、出题、建议」四类 AI 能力结合起来，
让大模型在**真实的学习数据**上工作，而不是做成一个与业务无关的聊天窗口。
系统同时提供管理端，用于用户、内容、AI 用量与系统配置的治理，使系统具备可运营性。
课题成果既是一套可运行的软件系统，也是一次关于"LLM 应用工程化"的完整实践，具有一定的实用价值与扩展能力。

---

## 二、课题研究内容与要求

本课题需完成一套前后端分离的 Web 系统，覆盖用户管理、学习资料管理、学习计划与任务跟踪、
智能学习辅助、学习数据分析与个性化推荐等功能，并配套管理端。具体要求如下：

1. **功能完整**：用户可上传课程资料并完成解析，系统能基于资料提供 AI 问答、总结、出题与建议；
   学习计划可生成每日任务，任务完成自动记录学习时长；统计数据可图表化展示。
2. **结构清晰**：采用分层架构（接口层 → 业务层 → 数据层），AI 能力独立成层，
   模型调用、工具、校验、用量各自职责单一，便于替换模型供应商与扩展场景。
3. **运行稳定**：AI 调用具备超时、重试、降级与配额控制；异常统一为结构化错误体；
   关键链路有自动化测试覆盖。
4. **数据安全**：用户数据严格按账号隔离，AI 工具只读且由服务端注入用户身份，模型无法越权；
   管理端写操作全部留痕审计。
5. **可扩展**：模型供应商、提示词、工具与场景均可配置或低成本替换；数据库结构可通过迁移演进。

## 三、功能模块划分

### 3.1 用户端功能（功能 1–6）

| 编号 | 功能 | 主要实现内容 |
|---|---|---|
| 1 | 用户注册登录 | 注册、登录、JWT 访问令牌 + httpOnly 刷新 Cookie、登出；改密/改角色后旧令牌立即失效 |
| 2 | 个人信息管理 | 修改昵称、头像、学习目标、每日目标时长；修改密码；查看个人学习信息 |
| 3 | 学习资料管理 | 上传 PDF / Word，流式落盘并做扩展名、大小、文件头三重校验；正文解析与分片读取；分类、搜索、下载、删除 |
| 4 | 在线笔记管理 | 笔记创建、编辑、删除、标签分类与关键词搜索；列表不返回完整正文 |
| 5 | 学习计划管理 | 设定目标、起止日期与每日时长；计划进度与完成率；一键生成每日任务（幂等） |
| 6 | 学习任务管理 | 按日期/状态筛选；完成任务自动写入学习记录并累计时长；跳过与删除 |

### 3.2 智能辅助功能（功能 7–10）

| 编号 | 功能 | 主要实现内容 |
|---|---|---|
| 7 | AI 智能问答 | 基于资料检索的问答，SSE 流式输出；模型可调用只读工具检索资料与学习数据；回答落库并计费 |
| 8 | AI 学习资料总结 | 对资料正文生成结构化总结与 5–10 条要点；长文档自动分段归并（map-reduce） |
| 9 | AI 学习测试生成 | 按题型、数量、难度生成题目并做**业务二次校验**（数量、选项、答案范围、题干去重）；支持答题、判分与逐题解析 |
| 10 | 个性化学习推荐 | 规则层：依据任务、薄弱知识点、计划与学习时长生成可解释推荐；AI 层：结合统计生成叙述性学习建议（两层互补） |

### 3.3 数据分析功能（功能 11–12）

| 编号 | 功能 | 主要实现内容 |
|---|---|---|
| 11 | 学习数据统计分析 | 学习时长、活跃天数、连续天数、任务完成率、答题正确率、科目分布；趋势数据**后端补零**，前端直接绘图 |
| 12 | 学习记录管理 | 记录学习时间、时长、类型与关联任务/资料；为统计与推荐提供数据源 |

### 3.4 管理端功能（功能 13）

| 子模块 | 主要实现内容 |
|---|---|
| 13.1 仪表盘 | 全站用户、内容、学习与 AI 用量指标；每日趋势 |
| 13.2 用户管理 | 用户检索与筛选、启用/禁用（必填原因）、角色调整、重置密码、强制下线；**禁止对自己执行危险操作** |
| 13.3 内容管理 | 跨用户查看资料/笔记/测试题（列表不下发正文与答案）、下架与重新解析 |
| 13.4 AI 用量监控 | 按场景、用户、日期统计调用与 token；调用明细筛选与分页 |
| 13.5 配置与审计 | 运行时配置（AI 开关、每日配额、注册开关、上传上限）即时生效；管理操作审计（与业务同事务、只增不改） |

## 四、关键技术

1. **大语言模型应用技术**
   基于 LangChain `create_agent` 构建四类场景（qa / summary / quiz / advice）；
   以 Pydantic 结构化输出约束模型返回，并做业务二次校验与重试；
   问答采用 SSE 流式事件协议（meta → tool → delta → done / error）；统一记录 token、步数与耗时，按日配额限流。

2. **文档解析与文本处理技术**
   采用 PyMuPDF、python-docx 提取 PDF / Word 正文，处理分页、空文本与扫描件判定；
   按字符偏移提供分片读取，长文档按阈值切分后归并，避免超出模型上下文。

3. **前后端分离开发技术**
   前端 React 19 + TypeScript + Vite + Ant Design + TanStack Query + ECharts；
   后端 Python 3.12 + FastAPI（异步）+ SQLModel；接口契约先行，统一错误体 `{code, message, detail}`。

4. **数据库设计与管理技术**
   PostgreSQL 18 + SQLAlchemy 异步驱动 + Alembic 迁移；
   合理使用 JSONB（题目、答卷、配置）、数组、部分唯一索引与软删除；
   统计不落冗余列，统一聚合查询。

5. **数据可视化技术**
   基于 ECharts 展示学习时长、任务完成、正确率趋势、科目分布与学习热力图；
   图表数据由后端补零，前端不做二次加工。

6. **个性化推荐技术**
   规则推荐：按「复习薄弱点 > 推进计划 > 补学习习惯」的优先级生成可解释建议，秒回且不消耗 AI 配额；
   AI 建议：由模型综合统计生成叙述性建议，数值部分由后端计算并覆盖模型输出，保证可信。

7. **身份认证与权限技术**
   OAuth2 Password Bearer + JWT + Argon2 密码哈希；
   角色**读库判定**、`token_version` 吊销机制；管理端独立鉴权，越权返回 403。

8. **部署与运维技术**
   Docker Compose 编排 PostgreSQL + 后端 + 前端（nginx 静态托管与 API 反代）；
   后端容器启动自动执行数据库迁移；敏感配置通过环境变量注入。

## 五、技术路线

```text
浏览器（React SPA）
      │  同源 /api/v1（生产由 nginx 反代）
      ▼
FastAPI 接口层（鉴权、参数校验、统一错误体）
      ▼
业务层（资料 / 笔记 / 计划 / 任务 / 记录 / 统计 / 推荐 / 管理端）
      ▼                         ↘
PostgreSQL（14 张表）           AI 层（LangChain Agent）
文件存储（上传资料）              ├─ 只读工具：资料检索、学习统计、待办、薄弱点
                                 ├─ 结构化校验与重试
                                 └─ 用量与配额（ai_usage）
                                        ▼
                                  外部大模型（OpenAI 兼容接口，可替换供应商）
```

AI 场景与工具：

| 场景 | 工具 | 输出 |
|---|---|---|
| qa 问答 | 资料检索、分片读取、学习统计、待办 | 流式文本 |
| summary 总结 | 无（正文随消息注入） | `SummaryOut` |
| quiz 出题 | 无（正文随消息注入） | `QuizOut` |
| advice 建议 | 学习统计、待办、薄弱点 | `AdviceOut` |

## 八、课题特色与创新点

1. **把大模型放进学习闭环**：AI 不是孤立聊天框，而是读取计划、任务、记录与答题数据后给出建议，
   并可通过工具按需检索资料，回答有据可依。
2. **契约先行**：接口、数据库与 AI 工具均有书面契约作为代码上游，接口/字段变更先改契约再改实现，
   降低前后端与 AI 层之间的耦合。
3. **AI 工具只读 + 身份注入**：模型只能读取当前用户的数据，写操作一律回到业务层，避免越权与脏写。
4. **结构化输出 + 业务二次校验**：模型返回先过 Pydantic，再过业务规则（题目数量、选项、答案范围、题干去重），
   不通过自动重试，仍失败再降级报错。
5. **规则推荐与 AI 建议分层**：规则层秒回、可解释、不耗配额；AI 层提供叙述性建议。
   数值类结论由后端计算覆盖模型输出，保证统计口径可信。
6. **成本与稳定性工程**：按日配额、逐次用量记账、超时与步数上限、供应商可插拔（只改环境变量）。
7. **可治理的管理端**：用户、内容、AI 用量与运行时配置统一管理；管理操作与业务变更同事务写审计，
   下架内容不影响历史统计口径。
