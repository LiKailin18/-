## 1. 系统概述

一个面向个人学习者的 Web 系统：上传学习资料（PDF / Word）→ 解析正文 → 制定学习计划与每日任务 →
完成任务记录学习时长 → 借助大语言模型完成**问答、总结、出题、判分、学习建议** → 用图表呈现学习数据，
另设管理员端负责用户、内容、AI 用量与系统配置管理。

|---|---|---|---|

### 1.2 技术栈

设计要点（`docs/db.md`）：

- **软删除**（`deleted_at`）为主；`quiz_attempt` 不软删除（它是统计依据，下架题目后历史答卷仍计入统计）。
- **多租户过滤写在 SQL 里**：每条查询都带 `user_id = 当前用户`，越权统一返回 404。
- **枚举用 VARCHAR + CHECK**，不用 PG 原生 ENUM（`CLAUDE.md` §6）。
- **角色读库判定**：JWT 只带 `sub/pv/typ`，权限不信令牌里的角色声明。

## 4. 关键时序

### 4.1 登录与令牌刷新（功能 1）

```mermaid
sequenceDiagram
    participant U as 浏览器
    participant B as 后端 auth
    participant DB as PostgreSQL

    U->>B: POST /auth/login (username, password)
    B->>DB: 校验密码 hash（argon2）
    B->>U: access_token（内存）+ refresh_token（httpOnly Cookie）
    Note over U,B: access 只存内存，刷新页面即失效

    U->>B: 带过期 access 调业务接口
    B-->>U: 401 AUTH_002
    U->>B: POST /auth/refresh（自动）
    B->>DB: 校验 refresh + token_version
    B->>U: 新 access_token
    U->>B: 重放原请求
```

### 4.2 AI 智能问答（SSE 流式 + 工具调用，功能 7）

```mermaid
sequenceDiagram
    participant U as 浏览器
    participant B as chat_service
    participant A as agent (create_agent)
    participant T as 只读工具
    participant M as 大模型

    U->>B: POST /ai/chat-sessions/{id}/messages/stream
    B->>U: event: meta (message_id)
    B->>A: graph.astream(stream_mode="messages")
    A->>M: 请求（带 tools 定义）
    M-->>A: tool_call (search_material)
    A->>T: search_material(keyword, user_id 闭包注入)
    T-->>A: 命中片段（信封 + 截断）
    A->>M: 工具结果
    M-->>A: 逐 token 文本
    A-->>U: event: delta* （打字机）
    A-->>U: event: done (usage)
    B->>B: 落库 user/assistant 消息 + 记用量
```

关键点：**工具只读**、`user_id` 由闭包注入（模型无法越权）、失败也落库（`ok=false`）、SSE 每 15s 心跳防代理断连。

### 4.3 管理员禁用用户（审计与业务同事务，功能 13.2）

```mermaid
sequenceDiagram
    participant A as 管理员
    participant B as admin/users
    participant S as admin_user_service
    participant DB as PostgreSQL

    A->>B: PATCH /admin/users/{id} {is_active:false, reason}
    B->>S: update_user(...)
    S->>DB: 校验目标非本人（否则 400 ADMIN_001）
    S->>DB: 置 is_active=false + token_version+1
    S->>DB: 写 admin_audit_log（from/to 快照）
    Note over S,DB: 同一次 commit —— 避免「改了但没记」
    B-->>A: 200 详情
    Note over A: 该用户的旧令牌全部立即失效
```

## 6. 关键设计取舍（答辩可讲）

1. **契约先行**：`api.md` / `db.md` / `agent-tools.md` 是代码上游，接口以「方法+路径表」为准。
2. **Access token 只存内存 + httpOnly refresh Cookie**：兼顾 XSS 与 CSRF，CSRF 用 Origin 校验。
3. **角色读库判定、`token_version` 吊销**：改密/改角色/禁用/强制下线即时生效。
4. **AI 只读工具 + 信封 + 截断 + 不抛异常**：模型无法越权，坏输出不影响系统。
5. **总结/出题不挂 `read_material_chunk`**：正文已由 service 注入，挂工具反而引发步数超限（实测 tokens 6651→870）。
6. **规则推荐（秒回、可解释）与 AI 建议（叙述性）分层**：两条线互补。
7. **管理端不提供 AI 生成接口**：成本与内容合规上的边界。
8. **下架题目不影响历史统计**：报表可复现。
9. **`app_setting` KV + 60s 缓存写后即清**：运行时开关无需重启。
10. **供应商可插拔**：模型只收敛在 `app/ai/llm.py`，换供应商改 `.env` 三个变量。

## 7. 部署

```bash
# 一键起全套（PG + 后端 + 前端 nginx）
docker compose -f deploy/docker-compose.yml up -d --build
# 打开 http://127.0.0.1:8080 ；后端 /health 看状态

# 第一个管理员（管理端不能给自己提权）
docker exec -it sls-backend python scripts/create_admin.py --username admin --email a@b.c --password xxx
```

- 后端容器启动时自动 `alembic upgrade head`；上传文件用 `uploads` volume 持久化。
- 敏感项（`LLM_API_KEY` / `SECRET_KEY`）从 `deploy/.env` 注入（不入库）。
